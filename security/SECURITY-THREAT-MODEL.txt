SERVICE-WORKER / REVOCATION DELIVERY NOTE
- Most application security logic is in the built index.html, which may be served from the PWA cache as an offline fallback.
- Future school-server revocation MUST therefore use a separately addressable security-critical resource guarded by network-only/no-store semantics; a revocation that depends only on replacing cached index.html is not an acceptable control.
- `access/suite-session-cleanup.js` and `ghrab/ghrab-platform.js` are deliberately NOT treated as revocation truth. They fetch fresh bytes first with `cache: no-store`, but fall back to the install/last-known cache when offline, because silently losing cleanup/platform controls on a shared device is a larger privacy/availability risk than using the last-known support implementation.
- This exception does not apply to revoked-access, access-control/app-guard, release-integrity, integrity-status, runtime-config or API/auth/session/health state; those remain fail-closed network-only.
