GARP 2.5.1 – AI RESOURCE BUDGET
Application: generator 7.1.24

Global request controls
- browser file selection: max 12 files; max 20 MiB each.
- AI runtime request cap: 18 MiB; max single part 14 MiB.
- embedded text cap: 300 KiB source bytes and 24,000 normalized chars; AI source text cap 24,000 chars.
- request timeout: 180,000 ms.
- gatewayMaxRetries: 0 in shared AI runtime config; app repair/validation loops are separately bounded.
- automatic provider fallback: false by deployment profile; direct Gemini fallback model list exists inside Core config but app mode selection/fallback is not autonomous.
- streaming: false for all registered operations.
- cancellation: AbortController/request cancellation is implemented for AI requests; suite end aborts active request.
- concurrency: UI workflow is designed around one active generation flow; no server-side per-user concurrency/rate enforcement exists in static profile. Treat server rate limits as SHIELD-LIVE requirement.

SHIELD-LIVE requirements before school production
- enforce authenticated per-user/per-app rate limits and request/body limits at gateway;
- cap concurrent requests and queue length;
- enforce provider/model allowlist outside browser input;
- server-side budget/usage observability without logging student prompt/output content;
- fail closed on unavailable authorization/budget service;
- document cancellation propagation from client -> gateway -> provider where supported.
